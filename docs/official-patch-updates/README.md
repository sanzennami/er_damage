### 旧缓存迁移

译名与改名对已经用过旧版本的浏览器不会自动生效（`localStorage` 保存值优先级更高），因此加了迁移逻辑，见 `src/data/dataMigrations.json` 与 `src/data/README.md`：

- **技能名**：保存值与迁移表记录的旧译名完全一致时才替换，用户自己改过的名字保持不变。
- **英雄名**：保存的英雄名若已不在实验体列表里（如 `Craver`），自动采用新名字；若用户把技能挪给了另一个真实存在的英雄，保留用户改动。

## 跟随版本更新（现行做法）

早期那两个脚本是**增量式**的一次性回填：以公告的「改前值」作校验基准，所以不能重跑，重跑前还得把数据还原回旧版本。
那是回填历史的思路，不适合跟着游戏版本走的工具，已经**废弃并归档**到 `scripts/archive/`（勿再运行）。

现行做法是**目标态收敛**：

- `src/data/patchLog.json` 记录每个补丁**之后应该是什么值**（不是"从 A 改成 B"）。
- `scripts/apply-patch-log.mjs` 把数据推到目标态，判断依据是**当前值是否已等于目标值**。
- 因此它**幂等、可以随时重跑**，永远不需要还原任何数据文件。

```bash
node scripts/apply-patch-log.mjs            # 应用全部补丁
node scripts/apply-patch-log.mjs --dry-run  # 只报告，不写文件
node scripts/apply-patch-log.mjs --from 12.0
```

### 出新版本时怎么做

1. 用 `hl=zh-CN` 抓公告（见本文开头的提醒）；
2. 在 `patchLog.json` 的 `patches` 末尾追加一段，`order` 取更大的数：

```jsonc
{
  "version": "12.1", "order": 120100, "date": "2026-08-13",
  "url": "https://playeternalreturn.com/posts/news/XXXX?hl=zh-CN",
  "title": "12.1 更新日志",
  "skills":     [ { "id": "external-leni-q-1069200-damage-stat1", "bases": "60,80,100,120,140",
                    "formula": "base + heroLevel * 8 + ap * 0.6", "coefficientText": "…" } ],
  "equipment":  [ { "name": "月水晶", "stat": "skillAmp", "value": 98 } ],
  "characters": [ { "hero": "雷妮", "path": "base.defense", "value": 55 } ],
  "mastery":    [ { "hero": "凯希", "type": "OneHandSword", "stat": "AttackSpeedRatio", "value": 0.035 } ]
}
```

3. 跑 `node scripts/apply-patch-log.mjs`。

脚本行为：

- 同一目标被多个补丁改过时，只应用**最新那次**，不会把被覆盖的中间值再写一遍；
- 数据被改乱或落后时，直接重跑就能拉回目标态（无需还原）；
- 标了 `"manual": true` 的技能**不会被自动覆盖**，只会列出「现用(人工)」与「官方新值」的对比，由你决定是否采纳；
- 装备属性 `remove: true` 表示删除该属性。

## 使用者注意

计算器会把配置保存在浏览器 `localStorage`（`er-damage-config-v1`）。**已经用过旧版本的浏览器会继续使用本地保存的旧技能数值**，需要清除该键（或清空站点数据）后刷新，才能读到本次更新的数据。

例外：英雄改名和本次记录在 `src/data/dataMigrations.json` 里的译名修正会自动迁移，不必清缓存。
但**数值**（基础伤害、系数、装备属性）仍然以本地保存值优先，想看到新数值就得清一次缓存。
